## 2024-06-25 - Prevent IDOR and Error Leakage in Backend
**Vulnerability:** The Express backend lacked authorization checks verifying if the requested resource ID in `/api/fhir/patient/:id` matched the authenticated user's ID (`req.session.tokenData.patient`), leading to an Insecure Direct Object Reference (IDOR). Additionally, all endpoints returned raw `error.message` or `error.toString()` on failure, potentially exposing sensitive stack traces or internal structure.
**Learning:** In a multi-tenant backend relying on session tokens for context, blindly trusting URL parameters (`:id`) without verifying them against the session's verified claims (`tokenData.patient`) exposes users to unauthorized data access. Explicit generic error messages must be favored over raw exception properties to uphold defense in depth and fail securely.
**Prevention:** Always implement explicit authorization checks validating URL/body identifiers against authenticated session state. Wrap internal operations in `try/catch` and return generic fallback error messages (e.g. `An internal server error occurred`) while logging raw errors internally.

## 2025-05-18 - Audit Express Backend FHIR Endpoints for IDOR and Stack Trace Leakage
**Vulnerability:** Express FHIR endpoints lacked central authorization middleware (`verifyPatientOwnership`) and central error handling, leading to potential IDOR where an authenticated user could request resource IDs belonging to other patients, and potential error leakage in production when unhandled rejections occurred.
**Learning:** Inline route checks were scattered and unstandardized. Unhandled exceptions in Express routes without an `asyncHandler` wrapper or global error handler middleware could crash or return default Express error pages containing stack traces.
**Prevention:** Modularize FHIR routes and protect them with standard `authMiddleware` and `verifyPatientOwnership` middleware. Wrap route handlers with `asyncHandler` and mount a global `errorHandler` middleware that sanitizes response outputs when `NODE_ENV === 'production'`.
