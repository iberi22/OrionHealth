## 2026-07-25 - IDOR in FHIR Patient Endpoint and Information Disclosure in Error Handlers
**Vulnerability:** The `/api/fhir/patient/:id` endpoint lacked an authorization check, allowing any authenticated user to retrieve another patient's data by guessing their `id` (IDOR). Additionally, global error handlers leaked the exact backend error messages (`error.message` and `error.toString()`) to the frontend, exposing implementation details.
**Learning:** The absence of authorization validation verifying that the requested resource ID matches the authenticated user's token (`req.session.tokenData.patient`) created the IDOR. The information disclosure was caused by indiscriminately passing raw exception details to the response body instead of returning a controlled, generic error message.
**Prevention:** Always implement explicit authorization checks on endpoints accessing specific resources, ensuring the requested identifier matches the user's authenticated scope/ID. Furthermore, fail securely by logging exact errors securely to standard error/logs, while returning generic, unrevealing error messages (e.g., "An error occurred") to clients.
