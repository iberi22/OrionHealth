## 2024-07-26 - API Backend Security Improvements
**Vulnerability:** IDOR in the FHIR endpoint and exposed server error details.
**Learning:** The FHIR patient endpoint was receiving a specific patient ID directly from the URL but was not verifying that this ID matched the currently authenticated user's ID stored in the session. This would allow an authenticated user to specify another user's patient ID and read their medical records (IDOR - Insecure Direct Object Reference). Additionally, sensitive stack traces and specific API error messages were being leaked back to the client via `res.status(500).json({ error: error.message })` and `res.status(500).send(error.toString())`.
**Prevention:** Always implement explicit authorization checks on endpoints accessing specific resource IDs to ensure they match the authenticated user's ID (e.g., `req.session.tokenData.patient`). Fail securely in error handling by returning generic error messages (e.g., 'An error occurred') instead of leaking sensitive backend or API details to the client.
